## Build & Test

```bash
swift build -c release    # compile only
swift test                # 64 unit tests
./setup.sh                # build + install to /Applications (dev, DEBUG_UI)
./build-pkg.sh            # unsigned test pkg (DEBUG_UI)
./build-pkg.sh --sign     # signed + notarized release pkg (no DEBUG_UI)
```

## Key Design Decisions

These are non-obvious constraints. Getting them wrong causes bugs.

- Layout math uses AppKit **points** (DPI-independent); output slices use **native pixels** (`pointSize * backingScaleFactor`). Critical for mixed-DPI multi-monitor setups.
- Wallpaper apply must happen on the **main thread** (`NSWorkspace.setDesktopImageURL` requirement).
- **Span mode** uses the full pipeline (load, crop, slice, write JPEG, apply). **Fit/Fill** skip it entirely and pass the original image to `NSWorkspace`.
- **Cross-process locking** via `flock` on all wallpaper-apply paths prevents the UI process and launchd agent from interleaving `NSWorkspace` calls.
- **Skip marker** (`.skip-next-tick`): written before installing the launchd agent so `RunAtLoad` exits without double-applying. Consumed on read. On reboot, no marker exists, so `RunAtLoad` works normally.
- **Start order**: `RotationManager.start()` calls `applyNext()` before `installLaunchAgent()` — first image must be applied and `lastImagePath` persisted before the agent fires.
- **Shuffle state is in-memory only**. Resets on rescan, retire, play mode change, or app restart. LaunchD ticks (separate process) degrade to random.
- `NSWorkspace.setDesktopImageURL(_:for:options:)` is deprecated in macOS 14+. No replacement API exists yet.
- **BuildInfo.swift** is generated by build scripts before compiling. The checked-in copy has placeholders so bare `swift build` works.
- **DEBUG_UI compile flag**: test builds pass `-Xswiftc -DDEBUG_UI`; signed releases do not. The Debug section in preferences is wrapped in `#if DEBUG_UI`.
- **Cache management** requires Full Disk Access (FDA). FDA is checked via `TCC.db` readability probe — auto-purge only runs from the launchd `--rotate` tick, never during interactive use.

When the user's request matches an available skill, invoke it via the Skill tool. When in doubt, invoke the skill.

Key routing rules:
- Product ideas/brainstorming → invoke /office-hours
- Strategy/scope → invoke /plan-ceo-review

- Full review pipeline → invoke /autoplan
- Bugs/errors → invoke /investigate
- QA/testing site behavior → invoke /qa or /qa-only
- Code review/diff check → invoke /review
- Visual polish → invoke /design-review
- Ship/deploy/PR → invoke /ship or /land-and-deploy
